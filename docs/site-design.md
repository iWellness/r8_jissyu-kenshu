# 実習研修コース Web教科書 設計書

作成日: 2026-09-08

状態: 実装済み。2026-09-09にshadcn/uiを使う簡潔な画面構造へ改訂。
関連文書: [実装指示書](implementation-guide.md)

## 1. 目的と設計判断

受講者がブラウザーとターミナルを並べ、「説明を読む → コマンドをコピーする → 実行する → 結果を確認する」を迷わず繰り返せる教科書を作る。

採用構成は **Astroの静的サイト + MDX本文 + shadcn/uiと専用の教材コンポーネント + GitHub Pages** とする。教材を既存の `.md` に保つことは要件としない。MDXは文章中にコマンド枠や確認欄を置きやすいため選ぶ。画面のレイアウトや操作はAstroコンポーネントが担当し、本文にHTMLやCSSを大量に書かない。

コマンド原文は独立したUTF-8テキストファイルに保存する。同じ文字列から表示とコピーを生成する。本文・表示用コード・コピー用コードの三重管理を避ける。

### 技術の比較

| 候補 | この教材との適合 | 判断 |
| --- | --- | --- |
| Astro + MDX + shadcn/ui | 文章を中心に、アクセシブルな共通部品と教材専用のコピー操作を組み合わせられる | 採用 |
| Astro + Starlight | 標準的なドキュメント機能を早く揃えやすい | 今回は7章程度で、実習用の画面を直接管理する方針のため不採用 |
| Zensical | 既存Markdownからの移行が簡単 | 前案。教材用の部品と操作を設計する自由度を優先して変更 |
| 手書きHTML/CSS/JS | 小規模なら実現可能 | 章ナビ・目次・部品の共通管理を別途作る必要がある |
| React中心のSPA / Next.js | 複雑な状態管理やサーバー機能に向く | 本教材に必要なブラウザー操作は小規模なため採用しない |

専用UIには保守コストがある。部品数を限定し、検索は既存ツールを使い、独自ルーターや独自の検索エンジンは作らない。

## 2. 技術スタック

| 領域 | 採用 | 用途 |
| --- | --- | --- |
| サイト生成 | Astro、`output: 'static'` | 各章をHTMLとしてビルド |
| 本文 | `@astrojs/mdx`、Content Collections | 文章と教材部品、メタデータ検証 |
| 実装言語 | TypeScript strict | 部品の入力と章データの型検証 |
| UI・スタイル | shadcn/ui（Base UI）、React、Tailwind CSS 4、CSS custom properties | 共通部品、配色、余白、レスポンシブ、印刷 |
| コード表示 | Shikiによるビルド時ハイライト | Bash/Python等を読みやすく表示 |
| ブラウザー操作 | 小さなTypeScriptスクリプト | コピー、検索UI、画像拡大、モバイルメニュー |
| 検索 | Pagefind | 生成したHTMLから日本語検索索引を作成 |
| 検証 | Astro check、Vitest、Playwright | 型・データ・コピー・画面・リンクの検証 |
| 依存管理 | npm、package-lock.json | CIは`npm ci`で再現 |
| 公開 | GitHub Actions、GitHub Pages | 検証済みの`dist/`を公開 |

具体的なパッケージ版は実装開始時に公式の対応関係を確認して選定し、lockfileへ固定する。Node.jsは選定したAstroが対応するLTSを固定し、ローカルとCIを一致させる。Pythonが必要になった場合はuvを使う。

サーバー、データベース、認証、SSRアダプターは導入しない。Reactはshadcn/uiの静的なサーバー描画に限定する。ページ遷移は通常のリンクとし、JavaScript無効でも本文・章移動・コード選択が使えるようにする。

## 3. 情報構造

すべてのURLはGitHub Pagesのbaseパス配下。章番号は表示順で管理し、URLに含めない。

| 既存原稿 | 新URL | ページ名 |
| --- | --- | --- |
| README.md | `/` | 研修の進め方・教材目次 |
| 00_vscodeの画面.md | `/lessons/vscode/` | VS Codeの画面とターミナル |
| 01_Linuxコマンド.md | `/lessons/linux/` | Linuxコマンド |
| 02_conda環境の設定.md | `/lessons/conda/` | conda環境の設定 |
| 03_qiime2のインストール.md | `/lessons/qiime2-install/` | QIIME 2のインストール |
| 04_JupyterLabのインストール.md | `/lessons/jupyterlab/` | JupyterLabのインストール |
| 05_qiime2.md | `/lessons/qiime2/` | QIIME 2解析 |
| 06_Claude_CodeでPython演習.md | `/lessons/python-practice/` | Claude CodeでPython演習 |

初版の章順は現存するファイルの00〜06を採用する。READMEの古い番号や、実体のないnano・Nextflowのリンクをそのまま移植しない。`pre-install.md`は講師準備用の候補として移行一覧に記録し、受講者向けページの生成対象には含めない。

トップページはh1「実習の流れ」、全7章のカード、実習前の注意だけで構成する。紹介ヒーローや開始ボタンは置かない。

## 4. 画面設計

デスクトップの構造:

```text
研修名                                     教材内を検索
───────────────────────────────────────────────────
章一覧 220px   章タイトル・目標
現在章        実行場所 / 必要な環境
              折り畳みのページ内目次
              手順の説明
              ┌ ターミナル / bash ─────── コピー ┐
              │ コマンド                           │
              └────────────────────────────────────┘
              期待される出力 / 完了条件
              前の章                     次の章
```

- 本文幅は最大800px、全体は最大1100px。ページ内目次は画面幅によらず本文冒頭の折り畳みに置く。
- 900px未満は章一覧もメニューボタンへまとめる。受講者がPC画面を半分にした幅でも本文を優先する。
- 本文17px程度、行高1.8、コード14〜15px程度。日本語はシステムフォント、コードは等幅フォント。
- 白背景、濃いグレーの文字、濃い青緑のアクセント。装飾より見出しと余白で構造を伝える。
- コードは明るいグレー背景と境界線。コピー操作はホバー不要で常時表示する。
- 長いコードは枠内で横スクロール。ページ全体を横スクロールさせない。折り返し表示を設ける場合もコピー原文は変えない。
- 実行場所は「ターミナル」「Jupyterのセル」「Claude Codeへの入力」など日本語で表示する。
- 注意は見出しとアイコンも併用し、色だけで意味を伝えない。補足のみ折り畳み可能。必須手順は常に表示する。
- 画像はキャプションと代替テキストを付け、クリックで原寸を確認できる。拡大ダイアログはEscで閉じ、起点にフォーカスを戻す。
- 見出しへ直接リンクできる。固定ヘッダーで見出しが隠れないよう`scroll-margin-top`を設定する。
- 印刷時はナビ・検索・ボタンを隠し、本文・コード・注意を残す。コードは印刷時のみ折り返す。

## 5. コマンド表示とコピーの仕様

### 共通原則

1. コマンド・出力・途中入力の練習・編集が必要な例を区別する。
2. 入力する文字列に、見せるためだけの`$`や行番号を混ぜない。
3. コピーはクリックまたはキーボード操作時だけ実行する。自動貼り付けやコマンド実行は行わない。
4. ハイライト済みHTMLの`innerText`をコピー元にしない。元テキストを安全にエスケープした隠し領域に保持し、DOMから原文を取得する。`innerHTML`への未検証文字列挿入は禁止する。
5. テキスト原文はUTF-8、LF。タブ・空白・引用符・行継続の`\`・本文内の空行を維持する。コピー時は末尾のLFだけを除去し、末尾Enterによる意図しない実行を避ける。`trim()`で前後の空白を削除しない。
6. 表示にも同じ正規化済み文字列を用いる。コメントは勝手に削除せず、長い説明を本文に移す場合は教材編集として記録する。
7. クリックしたブロックだけをコピーする。「章全体を実行」のボタンは設けない。

### 種別

| 種別 | 表示と操作 |
| --- | --- |
| command | 実行場所と言語を表示。「コピー」ボタン |
| template | 「値の書き換えが必要」と対象値を表示。「例をコピー」ボタン |
| practice | 「ここまで入力してTab」等を明示。コピーボタンなし、選択は可能 |
| output | 「期待される出力」。コピーボタンなし、選択は可能 |
| prompt | Claude Code等への依頼文。「依頼文をコピー」ボタン |

`fff`・`rrr`が残るDADA2コマンドはtemplateに分類する。初版は入力フォームや文字列の自動置換を実装しない。品質確認後に自分で決める値として本文で説明する。

### コピーの状態

- 初期: 「コピー」。操作中は重複クリックを抑止する。
- 成功: 「コピーしました」を`aria-live="polite"`で通知し、約2秒後に元へ戻す。
- Clipboard APIが使えない／拒否された場合: 成功表示にせず「コピーできませんでした。コードを選択してコピーしてください」と案内する。原文の選択は常に可能にする。
- JavaScriptが無効な場合: 動かないボタンを出さず、通常の文字選択でコピーできる表示にする。

## 6. 本文と部品のデータ契約

章メタデータはContent Collectionsで検証する。コレクションは`src/content.config.ts`で定義し、ローカルMDXをglob loaderで読み込む。

| フィールド | 型・制約 | 用途 |
| --- | --- | --- |
| slug | 英小文字・数字・ハイフン、重複不可 | 固定URL |
| order | 0以上の整数、重複不可 | 章の順序 |
| title | 空でない文字列 | h1、ナビ |
| description | 空でない文字列 | 目次、検索説明 |
| objectives | 1件以上の文字列配列 | 章の到達目標 |
| prerequisites | 文字列配列 | 実行前提 |
| environment | 空でない文字列 | 実行する環境 |
| reviewedAt | 任意のISO日付文字列 | 実際に内容を確認した日。ビルド日で代用しない |

部品の公開契約:

| 部品 | 入力 | 振る舞い |
| --- | --- | --- |
| CommandBlock | id、code、language、kind、context、title、必要ならreplacementNotes | idはページ内一意。kindはcommand/template/practice/prompt。templateにはreplacementNotes必須 |
| ExpectedOutput | code、caption | 出力表示専用、実行操作なし |
| Callout | type: note/warning/check、title、本文slot | 注意・補足・完了条件 |
| Figure | 画像import、alt、caption | 画像表示と拡大、寸法確保 |

MDXから部品をimportし、コードファイルを`?raw`で読み込んで渡す。import例はプロジェクト内エイリアスを使う。各部品のProps、既定値、必須条件、アクセシビリティ、エラー動作、使用例を実装時の`docs/authoring.md`に記載する。

## 7. 検索・素材・配信

- HTMLに`lang="ja"`を設定する。Pagefindはビルド後に実行する。
- 本文と見出しを検索対象にし、章ナビ・コピー通知・コピー元の隠し領域は除外する。検索結果は章タイトルと抜粋を表示する。
- 日本語と技術用語の混在を想定し、「環境」「インストール」「DADA2」「conda activate」を受け入れテストにする。
- 検索索引のロード失敗と検索結果0件を区別する。失敗時も章一覧から移動できる。
- 画像は`src/assets/`へ必要分だけ移し、Astroの画像処理を使う。既存画像と本文の対応を移行一覧で管理する。
- `data/`にはFASTQ等の教材データがある。ディレクトリ全体を`public/`へコピーしない。初版は必要なファイルへの明示的なダウンロードリンクを管理し、公開先・ファイル名・サイズ・取得確認を記録する。公開URLがない必要教材はリリース前の未完了項目とする。
- `site`は実リポジトリ所有者のPages origin、`base`は実リポジトリ名から設定する。所有者は現時点で未確認。カスタムドメインは初版対象外。
- 章リンク、画像、検索アセット、404からの戻り先をbase対応にする。GitHub PagesのプロジェクトURLの途中階層に直接アクセスしても表示される構成にする。

## 8. 移行時に解決する既存の問題

- READMEの目次と現存ファイル名が一致しない。新しい章データをナビの唯一の管理元にする。
- 原稿内にh1が複数あるページがある。ページタイトルのみh1とし、本文をh2/h3へ整理する。
- QIIME 2解析原稿のDADA2例は`--o-base-transition-stats`行の末尾に行継続がなく、次行の`--p-n-threads 3`が別コマンドになる。対象バージョンの公式仕様と合わせて確認し、修正差分と回帰テストを残す。
- `/home/coder`と`/home/r8user`の記載が混在する。実習環境を確認するまでは「出力例」と明示し、固定ユーザー名の完全一致を合格条件にしない。
- QIIME 2の環境・分類器・スクリーンショットには年度差がある。教材が指定する2026.1との整合を確認する。サイト移行を理由に解析ソフトを自動的に最新版へ変更しない。

既存原稿は初版移行中に削除しない。移行完了後は新MDXを編集の正本と明記し、旧原稿を参照資料として扱う。ファイル移動・URL・編集手順の変更は移行記録へ記載する。

## 9. 初版の完成条件

- 全7章、トップページ、404、章ナビ、ページ内目次、検索、画像拡大、印刷CSSが揃う。
- すべての実行コマンドが実行場所と適切な種別を持つ。
- 複数行コマンドのコピーが原文の正規化仕様と一致する。
- 1440px、768px、390pxで本文やボタンが切れず、ページ全体の横はみ出しがない。
- キーボードでコピー・検索・メニュー・画像拡大を操作でき、フォーカスを見失わない。
- baseパス付きの本番相当ビルドで、内部リンク・画像・検索アセット・見出しアンカーの参照が通る。
- 自動テスト、ビルド、教材移行レビューを完了し、実行環境で未確認の解析内容は確認済みと表示しない。

進捗保存、ダークモード、クイズ、パラメーター入力によるコマンド生成、ログイン、PDF自動生成は初版の対象外。まず授業での読解とコピーを完成させる。
